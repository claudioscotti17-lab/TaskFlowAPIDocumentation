Get started with TaskFlow by creating a project, adding a task, and retrieving the project's task list.

By the end of this tutorial, you will have explored all five TaskFlow API endpoints and learned how to create, retrieve, update, and delete tasks within a project.

## Prerequisites

Before you begin, make sure you have:

- A valid TaskFlow API key.
- A terminal with cURL installed, or an HTTP client such as Postman.
- Basic familiarity with HTTP requests and JSON.

No SDK or additional dependencies are required.

## Base URL

Send all requests to:

```text
https://test-writechoice.onrender.com
```

## Authentication

Every request requires an API key in the `Authorization` header using the Bearer authentication scheme.

For more information about API keys and authentication, see the [Authentication guide](/authentication).

```http
Authorization: Bearer YOUR_API_KEY
```

Replace `YOUR_API_KEY` with your valid API key. Do not include the placeholder text in actual requests.

For requests containing JSON, include the following header:

```http
Content-Type: application/json
```

<Warning>
  Keep your API key private. Do not commit it to a public repository or include it in shared request examples.
</Warning>

## Create your first project and task

<Steps>
  <Step title="Create a project">

    A project groups related tasks. Before creating a task, you must create the project it belongs to.

    Send a `POST` request to `/projects`:

    ```bash
    curl --request POST \
      --url https://test-writechoice.onrender.com/projects \
      --header "Authorization: Bearer YOUR_API_KEY" \
      --header "Content-Type: application/json" \
      --data '{
        "name": "API Documentation Revamp",
        "description": "Technical documentation validation project"
      }'
    ```

    A successful request returns `201 Created` and a JSON object containing the new project's details.

    Example response:

    ```json
    {
      "project_id": "f29e7b0d-28dd-4206-b70c-918437ca2738",
      "name": "API Documentation Revamp",
      "description": "Technical documentation validation project",
      "created_at": "2026-11-16T13:20:38.686Z"
    }
    ```

    <Note>
      Save the `project_id` returned by your request. You will need it to create and retrieve tasks. The ID and timestamp above are from a sample successful request; your values will differ.
    </Note>

  </Step>

  <Step title="Create a task">

    Now create a task within your project.

    Send a `POST` request to `/tasks`, using the `project_id` returned in the previous step.

    ```bash
    curl --request POST \
      --url https://test-writechoice.onrender.com/tasks \
      --header "Authorization: Bearer YOUR_API_KEY" \
      --header "Content-Type: application/json" \
      --data '{
        "project_id": "YOUR_PROJECT_ID",
        "title": "Write API quickstart guide",
        "description": "Create a step-by-step getting started tutorial for TaskFlow API"
      }'
    ```

    Replace `YOUR_PROJECT_ID` with your project's actual ID.

    A successful request returns `201 Created`.

    Example response:

    ```json
    {
      "task_id": "946368b5-239c-404e-9a2c-839df19c97f5",
      "project_id": "f29e7b0d-28dd-4206-b70c-918437ca2738",
      "title": "Write API quickstart guide",
      "description": "Create a step-by-step getting started tutorial for TaskFlow API",
      "status": "pending",
      "created_at": "2026-11-16T13:21:22.278Z",
      "updated_at": "2026-11-16T13:21:22.278Z"
    }
    ```

    New tasks automatically receive the `pending` status.

    Save the returned `task_id` if you want to update or delete this task later.

  </Step>

  <Step title="Retrieve your project's tasks">

    Verify that your task was created by retrieving the list of tasks associated with your project.

    Send a `GET` request to `/projects/{project_id}/tasks`.

    ```bash
    curl --request GET \
      --url https://test-writechoice.onrender.com/projects/YOUR_PROJECT_ID/tasks \
      --header "Authorization: Bearer YOUR_API_KEY"
    ```

    Replace `YOUR_PROJECT_ID` with the ID returned when you created the project.

    A successful request returns `200 OK`.

    Example response:

    ```json
    {
      "project_id": "f29e7b0d-28dd-4206-b70c-918437ca2738",
      "total": 1,
      "tasks": [
        {
          "task_id": "946368b5-239c-404e-9a2c-839df19c97f5",
          "project_id": "f29e7b0d-28dd-4206-b70c-918437ca2738",
          "title": "Write API quickstart guide",
          "description": "Create a step-by-step getting started tutorial for TaskFlow API",
          "status": "pending",
          "created_at": "2026-11-16T13:21:22.278Z",
          "updated_at": "2026-11-16T13:21:22.278Z"
        }
      ]
    }
    ```

    The response includes:

    - `project_id`: The project whose tasks were retrieved.
    - `total`: The number of tasks associated with the project.
    - `tasks`: An array containing the project's task objects.

    If the project exists but contains no tasks, the API returns an empty `tasks` array and `total` equal to `0`.

  </Step>
</Steps>

## Update a task

After creating and retrieving your task, you can update its status to reflect its progress.

Send a `PATCH` request to `/tasks/{task_id}` using the `task_id` returned when you created the task.

```bash
curl --request PATCH \
  --url https://test-writechoice.onrender.com/tasks/YOUR_TASK_ID \
  --header "Authorization: Bearer YOUR_API_KEY" \
  --header "Content-Type: application/json" \
  --data '{
    "status": "done"
  }'
```

Replace `YOUR_TASK_ID` with the actual task ID.

A successful request returns `200 OK` with the updated task details.

Example response:

```json
{
  "task_id": "946368b5-239c-404e-9a2c-839df19c97f5",
  "project_id": "f29e7b0d-28dd-4206-b70c-918437ca2738",
  "title": "Write API quickstart guide",
  "description": "Create a step-by-step getting started tutorial for TaskFlow API",
  "status": "done",
  "created_at": "2026-11-16T13:21:22.278Z",
  "updated_at": "2026-11-16T13:25:00.000Z"
}
```

The `status` field now shows `done`, indicating that the task has been completed.

You can also use this endpoint to update a task's title or description.

## Delete a task

After completing your task, you can delete it using the TaskFlow API.

Send a `DELETE` request to `/tasks/{task_id}` using the `task_id` returned when you created the task.

```bash
curl --request DELETE \
  --url https://test-writechoice.onrender.com/tasks/YOUR_TASK_ID \
  --header "Authorization: Bearer YOUR_API_KEY"
```

Replace `YOUR_TASK_ID` with your task's actual ID.

A successful request returns `200 OK`, confirming that the task was deleted.

<Warning>
  Deleting a task is permanent and cannot be undone.
</Warning>

### Verify the deletion

To confirm that the task was removed, retrieve the project's task list again:

```bash
curl --request GET \
  --url https://test-writechoice.onrender.com/projects/YOUR_PROJECT_ID/tasks \
  --header "Authorization: Bearer YOUR_API_KEY"
```

If the deleted task was the project's only task, the response will look like this:

```json
{
  "project_id": "f29e7b0d-28dd-4206-b70c-918437ca2738",
  "total": 0,
  "tasks": []
}
```

If the project contains other tasks, they will remain in the response.

You have now completed the full task lifecycle: creating a project, creating a task, retrieving tasks, updating a task, and deleting a task.

## Understanding task statuses

Every task has a status that represents its current progress.

| Status | Meaning |
| --- | --- |
| `pending` | The task has not been started. |
| `in_progress` | Work on the task is underway. |
| `done` | The task has been completed. |

You can change a task's status using `PATCH /tasks/{task_id}`.

You can also update a task's title or description using the same endpoint. See the API Reference for the complete request schema and available responses.


## Troubleshooting

If a request fails, check the HTTP status code and the response body.

| HTTP status | Possible cause | What to do |
| --- | --- | --- |
| `400 Bad Request` | Required fields are missing or invalid. | Review the JSON request body and required fields. |
| `401 Unauthorized` | The API key is missing or invalid. | Check the Bearer token in the Authorization header. |
| `404 Not Found` | The referenced project or task does not exist. | Verify the project or task ID. |

<Note>
  Error responses contain an `error` field and a human-readable `message` field to help identify the problem.
</Note>

For detailed error examples and step-by-step solutions, see the [Troubleshooting guide](/troubleshooting).
